# 巡檢照片上傳

把 `維護照片相簿` 各相簿的照片批次放進巡檢檢核表。

工作流程三步：

```
① 一鍵產生所有相簿分頁   ← 腳本，全自動
② 人工排版               ← 填項目、調順序、需要的話把照片搬到 写真(前)
③ 發布到正式目標         ← 腳本，一次 copyTo 進老闆的活頁簿
```

腳本掛在 **[巡檢照片上傳（開發用）](https://docs.google.com/spreadsheets/d/1mm4uq3QTM9pSJGJ04KZPMJiIzulx597Ff1dAc1EJpTI/edit)**。
staging 分頁就在同一份試算表裡，不會另開檔案。

---

## 第一次執行

打開試算表 → 功能表 **Chloe的工具 → 一鍵產生所有相簿分頁**。

**會跳一次授權**，因為新增了建立觸發器的權限（自動續跑要用）。授權後可能要再按一次。

然後就不用管了。它會：

1. 掃描 `維護照片相簿` 的所有子資料夾，把七個相簿寫進「設定」分頁
2. 每個相簿建一個以相簿命名的分頁，排好格式
3. 依檔名順序把照片寫進 **写真(後)（C 欄）**
4. 撞到 Apps Script 的 6 分鐘上限就自己排一個觸發器續跑，**不需要你再按**

進度看「設定」分頁：`J1` 是整體狀態，每一列的「已寫入張數」和「狀態」是各相簿的進度。
276 張大概要跑好幾輪，每輪之間隔 30 秒。

### 該看到什麼

七個分頁，張數分別是：京吹雪 32、緣宿 41、唐物a 49、唐物b 32、寶柿 40、風舍 43、唐物c 39。

每個分頁：第 1 列是 `項目 / 写真(前) / 写真(後) / 備註` 並凍結；照片在 C 欄第 2 列起，
一列一張不溢出；A 欄點下去有 37 項下拉；B、D 欄空白。

某張照片抓不到時，那一格會寫 `⚠ 抓不到 IMG_xxxx.HEIC`，並在該列的「狀態」欄列出來。
留字而不是留空，是為了讓進度能繼續前進——空格會讓那個相簿永遠判定成「沒做完」。

### 要重做某個相簿

刪掉那個分頁，再按一次「一鍵產生所有相簿分頁」。進度會自動歸零重來。
（沒有「重置」按鈕，因為刪分頁就是重置。）

---

## 排版

在 staging 分頁裡自由調整：填 A 欄項目、搬動照片、把某些照片剪到 写真(前)。
**只有你看得到**，共編檔完全不受影響。

排版不會被腳本弄壞：進度記在「設定」分頁的數字欄，不是從分頁內容推算的。
不過已經產完的相簿本來就不會再被寫入。

---

## 發布

1. 在「設定」分頁該列的 **發布目標試算表ID** 填入老闆那份活頁簿的 ID
   （網址 `/spreadsheets/d/` 與 `/edit` 之間那一段）
2. **Chloe的工具 → 發布到正式目標**
3. 確認框會顯示目標檔名、分頁名、張數，按「是」才會動

它會把整個分頁 `copyTo` 過去、改名成「發布分頁名」（例如 `0727Luna`）、移到最前面。
排版原封不動，因為照片是烘進試算表的，不是連結。

安全機制：分頁沒產完會拒絕發布；目標已有同名分頁會中止；`copyTo` 之後若改名失敗會
把殘留分頁刪掉再報錯。這是整套系統裡唯一會碰到共編檔的操作。

## 尚未驗證的兩件事

1. **`copyTo` 能不能把烘進去的圖片帶到另一個活頁簿。** 理論上可以（圖片存在
   Google 自己的儲存空間，不是連結），但沒實測過。建議先發布到一個你自己的空白
   試算表試一次，確認圖片有跟過去再對老闆的檔案動手。
2. **`openById` 打不打得開老闆的活頁簿。** 如果那份檔案是 Office 格式（.xlsx）而不是
   原生 Google 試算表，Apps Script 根本打不開，會立刻報錯。錯誤發生在對目標做任何事
   之前，不會留下痕跡。要先確認的話，把 ID 給我，用 `DriveApp.getFileById(id).getMimeType()`
   一行就能查。
