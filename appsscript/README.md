# 巡檢照片上傳

把 `維護照片相簿` 各相簿的照片批次放進老闆的巡檢檢核表。

```
① 建立／更新設定分頁      ← 腳本，掃 Drive
② 產生相簿分頁（匯入照片） ← 腳本，全自動、會自己續跑
—— 人工排版：填項目、調順序、需要的話把照片搬到 写真(前) ——
③ 發布到正式目標          ← 腳本，一次 copyTo 進老闆的活頁簿
```

腳本掛在 **[巡檢照片上傳（開發用）](https://docs.google.com/spreadsheets/d/1mm4uq3QTM9pSJGJ04KZPMJiIzulx597Ff1dAc1EJpTI/edit)**。
staging 分頁就在同一份試算表裡，不會另開檔案。

---

## ① 建立／更新設定分頁

掃 `維護照片相簿` 的子資料夾，一個相簿一列。**可以隨時重按**，只會補新的相簿，
不會覆蓋你改過的東西。

「發布目標」欄由程式自動帶入，是一個**檔案智慧型方塊**（點了直接開老闆那份活頁簿）。
對應規則是「相簿名去掉 `MMDD` → 老闆的巡房維護活頁簿」，寫在 `Config.gs` 的
`TARGETS` 對照表。顯示 `⚠` 表示對照表裡沒有這個物件，那一列不會被發布——
在對照表加一行就好。**這一欄不用也不要手填。**

欄位改版時舊表會變成 `設定_舊_<時間戳>`（不刪你的資料），兩個核取欄的狀態會搬過來。

## ② 產生相簿分頁（匯入照片）

語意就是字面上的意思：**勾了「匯入相片」就重新產生，沒勾就完全不碰。**
按下去等於「重來」——會先刪掉該分頁再從頭寫，動手前會把清單攤開讓你確認。
**排好版之後把該列的「匯入相片」取消勾選**，它就永遠不會再被動到。

它會依檔名順序把照片寫進 **写真(後)（C 欄）**，撞到 Apps Script 的 6 分鐘上限就
自己排觸發器續跑，**不需要你再按**。進度看「設定」分頁：`J1` 是整體狀態，
每一列的「狀態」欄是各相簿的進度。276 張大概要好幾輪，每輪間隔 30 秒。

### 該看到什麼

七個分頁，張數分別是：京吹雪 32、緣宿 41、唐物a 49、唐物b 32、寶柿 40、風舍 43、唐物c 39。

每個分頁：第 1 列是 `項目 / 写真(前) / 写真(後) / 備註` 並凍結；照片在 C 欄第 2 列起，
一列一張不溢出；A 欄點下去有 37 項下拉；B、D 欄空白。

某張照片抓不到時，那一格會寫 `⚠ 抓不到 IMG_xxxx.HEIC`，並在該列的「狀態」欄列出來。
留字而不是留空，是為了讓進度能繼續前進——空格會讓那個相簿永遠判定成「沒做完」。

## 排版

在 staging 分頁裡自由調整：填 A 欄項目、搬動照片、把某些照片剪到 写真(前)。
**只有你看得到**，共編檔完全不受影響。空白列可以用
**Chloe的工具 → 刪除本分頁的空白列** 收攏。

排版不會被腳本弄壞：續跑進度存在 `DocumentProperties`，不是從分頁內容推算的。
而且沒勾「匯入相片」的列，②根本不會碰。

---

## ③ 發布到正式目標

1. 把該列的「**發布**」欄勾起來（新相簿預設不勾）
2. **Chloe的工具 → 發布到正式目標**
3. 確認框會顯示**即時讀取的目標檔名**、分頁名、張數、檔案大小預估，按「是」才會動

它會把整個分頁 `copyTo` 過去、改名成「發布分頁名」（例如 `0727Luna`）、移到最前面。
排版原封不動，照片也跟著過去——圖片是烘進試算表的，不是連結（已實測，重開檔案後還在）。

發布目標**不讀設定分頁**，是發布當下用相簿名重新查對照表得到的。所以不存在
「欄位顯示一份檔、實際寫進另一份」的可能。

安全機制：分頁沒產完會拒絕發布；對照表查不到目標會拒絕；目標已有同名分頁會中止；
`copyTo` 之後若改名失敗會把殘留分頁刪掉再報錯。這是整套系統裡唯一會碰到共編檔的操作。

### 檔案大小

老闆的檔案是 `.xlsx`，而 Google 試算表**打不開超過 100MB 的 Office 檔案**。
好幾份已經逼近這條線，確認框會顯示預估值並在超過 90% 時警告。它不會擋你，
但看到 ⚠⚠ 就先別按。

## 改程式

```
clasp.cmd push      # 從專案根目錄執行，把 appsscript\ 推上去
```

Node 與 clasp 都在 `tools\` 裡，沒有裝到系統。改完推送，重新整理試算表即可。

用到 **Sheets 進階服務**（寫檔案智慧型方塊），已宣告在 `appsscript.json`，
不需要額外的 OAuth 範圍。
