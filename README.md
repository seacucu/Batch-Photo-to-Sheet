# 巡檢照片上傳

一支 Google Apps Script。把 Drive 相簿裡的巡檢照片批次貼進各物件的
「巡房維護」活頁簿——中間保留一段人工排版，因為「哪張照片對應哪個檢查項目」
沒辦法自動判斷。

```
① 建立／更新設定分頁        腳本：掃 Drive，一個相簿一列
         ↓
② 產生相簿分頁（匯入照片）   腳本：塞照片，撞到執行上限會自己續跑
         ↓
   —— 人工排版：填項目、調順序、需要的話把照片搬到 写真(前) ——
         ↓
③ 發布到正式目標            腳本：一次確認、整批 copyTo 進共編活頁簿
```

全部發生在腳本所在的那一份試算表裡。staging 分頁不另開檔案，排版期間
**只有你看得到**，共編檔完全不受影響，直到你按下 ③。

## 需要什麼

- 一個 Google 帳號，對以下東西有權限：
  - 放相簿的那個 Drive 資料夾（讀取就夠）
  - 各物件的「巡房維護」活頁簿（**編輯**，③ 要寫進去）
- 相簿的擺法：一個根資料夾，底下一個子資料夾就是一個相簿，照片直接放在子資料夾裡。
  檔名順序要等於你想要的照片順序（本專案的語料剛好是拍攝時間序）。

  ```
  維護照片相簿/            <- 這個的 ID 要填進 ROOT_FOLDER_ID
  ├── 0727京吹雪/          <- 一個相簿 = 設定分頁的一列
  │   ├── IMG_0001.HEIC
  │   └── IMG_0002.HEIC
  └── 0727緣宿/
  ```

  相簿名建議是 `MMDD` + 物件名，程式靠這個推導發布分頁名與對應目標。
- 要用指令推送程式的話：Node.js 與 [clasp](https://github.com/google/clasp)。
  不想裝也可以，直接在 Apps Script 編輯器裡貼程式碼（見下）。
  本 repo 的 `clasp.cmd` 包裝器驗證過 clasp **3.3.0**。

## 部署

### 步驟 1：準備一份試算表與綁定的腳本

腳本是**綁在試算表上**的（container-bound），不是獨立腳本——選單 `Chloe的工具`
要靠 `onOpen` 掛在那份試算表上。

新建一份 Google 試算表，取名例如「巡檢照片上傳（開發用）」，然後
**擴充功能 → Apps Script**。網址長這樣：

```
https://script.google.com/.../projects/<這一段就是 scriptId>/edit
```

### 步驟 2：把程式碼放進去

**方式 A — clasp（建議，之後改程式也用這個）**

把 `appsscript/.clasp.json` 裡的兩個 ID 換成你自己的：

```json
{
  "scriptId": "<步驟 1 拿到的 scriptId>",
  "parentId": "<那份試算表的 ID，網址 /d/ 後面那段>"
}
```

然後從**專案根目錄**執行：

```
clasp.cmd login     <- 只要做一次，會開瀏覽器
clasp.cmd push
```

`clasp.cmd` 會依序找：`tools\` 底下的可攜式 Node + clasp → PATH 上的 `clasp`
→ `npx @google/clasp`。`tools\` 不進 git，所以從 GitHub clone 下來會走後兩條，
要先 `npm install -g @google/clasp`。非 Windows 就直接用 clasp：
`cd appsscript && clasp push`。

> `clasp create-script --type sheets --title "巡檢照片上傳"` 可以一次把試算表
> 跟腳本都建好，但它會覆寫 `.clasp.json`，所以要在 `appsscript/` 裡跑，
> 跑完確認 `rootDir` 還是空字串。

**方式 B — 手貼**

在 Apps Script 編輯器裡把 `appsscript/` 的七個 `.gs` 檔各建一個同名檔案貼進去，
再到 **專案設定 → 顯示 appsscript.json** 把 `appsscript/appsscript.json` 的內容貼上。
`appsscript.json` 不能漏——時區、OAuth 範圍、Sheets 進階服務都在裡面。

### 步驟 3：填自己的 ID（**必做**）

`appsscript/Config.gs` 有兩個東西是寫死的，照你自己的環境改：

| 位置 | 填什麼 |
|---|---|
| `CFG.ROOT_FOLDER_ID` | 放相簿的那個根資料夾 ID |
| `CFG.TARGETS` | 物件名 → 目標活頁簿 ID 的對照表 |

`TARGETS` 的鍵是目標檔名去掉共通後綴剩下的部分。比對時兩邊都會過
`normalizeName_()`，它會**去掉開頭四位數字**並**移除「町」與空白**，所以
相簿 `0727唐物a` 對得上檔名 `唐物町a巡房維護.xlsx`：

```js
TARGETS: {
  '唐物町a': '1yS-rV2BVnCBDu5WobI8MFr80tVtvevCC',
  '京吹雪':  '1i1esSXS4Qx4DZINg_WRKlovhcaoHkBym',
  // ...
}
```

正規化後撞鍵會直接拋錯而不是猜——「安靜地對到錯的活頁簿」是這套系統最
不能容忍的失敗。對照表裡沒有的相簿，設定分頁會顯示 `⚠`，那一列不會被發布。

> **這些 ID 不是密碼**，但它們會洩漏你的資料夾結構與物件清單。repo 要公開的話，
> 考慮把 `ROOT_FOLDER_ID` 與 `TARGETS` 搬到一個 gitignored 的 `Config.local.gs`
> （Apps Script 共用同一個全域作用域，拆檔不需要 import），repo 裡只放範本。

另外可以順手改的：`CFG.ITEMS`（A 欄下拉的 37 個檢查項目）、
`CFG.HEADERS_SHEET`（分頁的四個欄位名，目前是 `項目 / 写真(前) / 写真(後) / 備註`）。

### 步驟 4：授權

重新整理試算表 → 選單出現 **`Chloe的工具`** → 按 **① 建立／更新設定分頁**。
第一次會跳授權畫面；因為是你自己的未驗證腳本，Google 會擋一次：
**進階 → 前往「專案名」（不安全）→ 允許**。

要授權的範圍（都宣告在 `appsscript.json`）：

| 範圍 | 用來做什麼 |
|---|---|
| `spreadsheets` | 讀寫試算表、③ 寫進目標活頁簿 |
| `drive.readonly` | 掃相簿資料夾、讀目標檔的大小 |
| `script.container.ui` | 選單與確認對話框 |
| `script.scriptapp` | ② 續跑用的時間觸發器 |

Sheets **進階服務**（寫「發布目標」欄的檔案智慧型方塊）也宣告在 `appsscript.json`，
`clasp push` 之後自動生效，不需要額外的 OAuth 範圍。

## 使用方法

### ① 建立／更新設定分頁

掃根資料夾的子資料夾，一個相簿一列。**可以隨時重按**：只補新相簿，
**絕不覆蓋你改過的東西**（包含兩個核取欄）。

唯一的例外是「發布目標」欄——它是從相簿名推導的衍生值，每次都整欄重寫。
不然對照表補好之後，一個過期的 `⚠` 會永遠黏在那裡。

配對依據是**來源資料夾 ID 而不是名稱**，所以相簿改名不會變成重複列。
欄位改版時舊表會被改名成 `設定_舊_<時間戳>`（不刪你的資料），兩個核取欄的
狀態會依資料夾 ID 搬到新表。

### ② 產生相簿分頁（匯入照片）

**勾了「匯入相片」就重新產生，沒勾就完全不碰。** 沒有「幫你判斷是否已完成」
的隱藏邏輯——那會讓勾選框控制不了它看起來在控制的東西。

按下去等於「重來」：先刪掉該分頁、進度歸零，再從頭寫。動手前會把清單攤開讓你確認。

照片依檔名順序寫進 **写真(後)（C 欄）**，一列一張。撞到 Apps Script 的
6 分鐘上限就自己排觸發器續跑，**不需要你再按**。進度看「設定」分頁：
`J1` 是整體狀態，每一列的「狀態」欄是各相簿的進度。兩三百張要跑好幾輪，
每輪間隔 30 秒。

**排好版之後把該列的「匯入相片」取消勾選**，它就永遠不會再被動到。

每個產出的分頁：第 1 列是四個欄位名並凍結；照片在 C 欄第 2 列起，一列一張
不溢出；A 欄點下去有 37 項下拉；B、D 欄空白。

> HEIC 不必處理。Drive 的 thumbnail 端點會在伺服器端解成 JPEG 並套好旋轉。

某張照片抓不到時，那一格會寫 `⚠ 抓不到 IMG_xxxx.HEIC`，並在該列的「狀態」欄
列出來。**留字而不是留空**是刻意的——空格會讓那個相簿永遠判定成「沒做完」，
進度就卡在那裡再也前進不了。

### 人工排版

在 staging 分頁裡自由調整：填 A 欄項目、搬動照片、把某些照片剪到 写真(前)。
空白列可以用 **`Chloe的工具` → 刪除本分頁的空白列** 收攏（Ctrl+Z 可以還原）。

排版不會被腳本弄壞：續跑進度存在 `DocumentProperties` 而不是從分頁內容推算，
而且沒勾「匯入相片」的列 ② 根本不會碰。

### ③ 發布到正式目標

1. 把要發布的那幾列的「**發布**」欄勾起來（新相簿預設不勾）
2. **`Chloe的工具` → 發布到正式目標**
3. **一個確認框列出整批要動的東西**，按一次「是」就全部發布

確認框會顯示每一筆的來源分頁、張數、即時讀取的目標檔名、目標分頁名，
各目標檔的大小預估，以及**哪幾列會被略過與原因**。按「是」之後不會再問。

流程是「全部檢查 → 一次確認 → 全部執行」。一份一份問的問題不只是手痠：
問到第五份時前四份已經寫進共編檔了，而你是在那之後才看到第五份有問題。

它把整個分頁 `copyTo` 過去、改名成「發布分頁名」（例如 `0727Luna`）、移到最前面。
排版原封不動，照片也跟著過去——圖片是烘進試算表的，不是連結。

發布目標**不讀設定分頁**，是發布當下用相簿名重新查 `TARGETS` 得到的。
所以不存在「欄位顯示一份檔、實際寫進另一份」的可能。

**會在動手之前就被攔下來的情況**（列在確認框裡，其他列照發）：

- 「發布分頁名」是空的
- 找不到 staging 分頁
- `TARGETS` 查不到對應目標
- 分頁還沒產完（進度 < 照片數）
- 目標已經有同名分頁
- 兩列要寫進同一份檔案的同一個分頁名

`copyTo` 成功之後才失敗（例如改名失敗）的話，會把殘留分頁刪掉再報錯，
不會在共編檔留下一個叫「xxx 的副本」的東西。

#### 檔案大小

目標是 `.xlsx`，而 Google 試算表**打不開超過 100MB 的 Office 檔案**。
確認框會按目標檔分組累加預估值（兩個相簿發到同一份檔案時會合計，分開算
會各自都說「還沒滿」），超過 90% 標 `⚠`、超過 100MB 標 `⚠⚠`。

**它不會擋你**，但看到 `⚠⚠` 就先別按——先把舊分頁搬到封存檔，或調低
`CFG.THUMB_WIDTH`。估值是每張約 145KB，來自實測（49 張的試算表 7,100,865 bytes）。

## 設定分頁的欄位

| 欄 | 名稱 | 誰填 | 說明 |
|---|---|---|---|
| A | 相簿名稱 | ① | Drive 子資料夾名。發布目標與發布分頁名都從這裡推導 |
| B | 來源資料夾ID | ① | 配對的鍵。別改 |
| C | staging分頁名 | ① 填空白 | 預設同相簿名，已消毒成合法分頁名。可以改 |
| D | 發布目標 | ① 整欄重寫 | **檔案智慧型方塊**，點了直接開目標檔。是輸出不是輸入，**不要手填** |
| E | 發布分頁名 | ① 填空白 | 預設 `MMDD` + `Luna`。相簿名沒有四位數字開頭時留空，要自己填 |
| F | 匯入相片 | **你** | 勾了 ② 就重做這一列。排完版請取消勾選 |
| G | 發布 | **你** | 勾了 ③ 才會發布。新列預設不勾 |
| H | 狀態 | 腳本 | 各相簿的進度與錯誤 |
| J1 | — | 腳本 | 整體狀態（觸發器沒有 UI，寫這裡）|

D、F、G 三欄的標題儲存格有備註，滑鼠移上去就看得到說明。

## 疑難排解

**選單沒出現** — 重新整理試算表。`onOpen` 只在開檔時跑。

**「找不到『設定』分頁」／「欄位格式不符」** — 先執行 ①。② 和續跑刻意只讀
不建、也不遷移 schema，那是 ① 的職責。

**② 停在半路不動了** — 看 `J1`。顯示「執行中，30 秒後自動續跑」就等它；
顯示「⚠ 已停止：這一輪沒有任何進展」表示卡住了，看各列的「狀態」欄。
再排下去只是空轉，所以它會自己停。

**「另一個執行正在進行中」** — 續跑觸發器正在跑，等它跑完。選單與觸發器
不會自動互斥，所以用了 `LockService`；兩邊同時跑會重複寫入並各自再排一個觸發器。

**設定分頁的「發布目標」顯示 `⚠`** — `TARGETS` 裡沒有這個物件。加一行，再按 ①。

**③ 說「還沒產完」但你覺得已經好了** — 進度 > 0 且 < 照片數才會擋。
進度是 0（例如換過 schema、或分頁是很久以前產的）不會擋——寧可放行也不要
誤擋一個好好的分頁。

**照片變成 `#REF!`** — 你大概在改程式時走回了 `=IMAGE()` 加 `PASTE_VALUES`
那條路。那條路現在不通，見 `legacy/README.md`。

**觸發器失敗通知信一直來** — 續跑時的例外會被重新拋出，讓 Google 寄信。
`catch` 裡一定會拆掉保險觸發器，所以不會變成每 7 分鐘無限重試。

## 專案結構

```
.
├── README.md
├── LICENSE
├── clasp.cmd                   可攜式 clasp 包裝（Windows）
├── appsscript/                 clasp 推送的根目錄
│   ├── .clasp.json             scriptId / parentId ← 部署時要改
│   ├── .claspignore
│   ├── appsscript.json         時區、OAuth 範圍、Sheets 進階服務
│   ├── Code.gs        (506)    選單、①、②、續跑迴圈、設定分頁 schema 與遷移
│   ├── Config.gs      (182)    全部常數：版面像素、TARGETS、37 項下拉
│   ├── Targets.gs     (120)    相簿名 → 目標活頁簿、寫檔案智慧型方塊
│   ├── Publish.gs     (277)    ③ 檢查／確認／執行、大小預警、回滾
│   ├── Photos.gs      (108)    列舉相簿、建 CellImage、退避重試
│   ├── Staging.gs      (89)    建立排好格式的分頁、分頁名消毒
│   └── Tools.gs        (65)    刪空白列
├── legacy/                     最早的原型（備查，不會被推上去）
└── tools/                      可攜式 Node + clasp（gitignored）
```

Apps Script 把同一個專案的所有 `.gs` 當成**一個共用的全域作用域**，沒有
import／export。所以檔案之間直接互相呼叫，但**函式名不能撞**。

程式碼裡的註解寫的是「為什麼」而不是「做什麼」，而且多半附著實測數據或
踩過的坑。要改哪裡之前先讀那段註解，可以省下重踩一次的時間。

## 調整參數

都在 `appsscript/Config.gs`：

| 常數 | 預設 | 改了會怎樣 |
|---|---|---|
| `COL_W_PHOTO` | 171 | 照片欄寬。**列高會自己跟著算**（`ROW_DATA` 是推導的，不要另外寫死）|
| `THUMB_WIDTH` | 1000 | 抓圖的像素寬。調小 → 檔案變小、畫質變差。少了這個參數只會拿到約 200px |
| `BATCH_SIZE` | 20 | 一次 `setValues` 幾張 |
| `SOFT_TIME_LIMIT_MS` | 4 分鐘 | 每輪跑多久就收手（硬上限是 6 分鐘）|
| `NEXT_CYCLE_MS` | 30 秒 | 續跑間隔 |
| `SAFETY_TRIGGER_MS` | 7 分鐘 | 保險觸發器。要排在任何執行都不可能還活著之後 |
| `EST_BYTES_PER_PHOTO` | 149000 | 大小預估。換了 `THUMB_WIDTH` 就該重新實測 |
| `ITEMS` | 37 項 | A 欄下拉。逗號串接有 500 字元上限 |

改完 `clasp.cmd push`，重新整理試算表即可。

## 已知限制

- **照片一律進 写真(後)**。前後配對不在範圍內，要自己剪貼。
- **順序 = 檔名順序**，不讀 EXIF 拍攝時間。
- **`TARGETS` 要手動維護**。新增物件時要加一行、推一次。
- **`normalizeName_()` 的規則是這個場域的慣例**（去掉開頭四位數字、移除「町」）。
  換場域要改這個函式。
- **一次 ③ 只能發一批**。同一個相簿要發到兩份不同的目標檔，沒有這個功能。
- **`clasp.cmd` 只有 Windows 版**。其他平台直接用 clasp。
